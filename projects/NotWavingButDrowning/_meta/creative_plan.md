# 《溺墨》創作計畫

## 核心

一個 35 歲作家在基隆公寓裡寫一部無限嵌套的小說，試圖透過書寫救贖三年前那個雨夜。他發現自己只是在不斷重複關上那扇書房門的罪。

## 里程碑

| 階段 | 內容 | 狀態 |
|------|------|------|
| M1 | 核心文件（_CONTEXT、outline、agent_guidelines、nesting_logic） | ✅ 完成 |
| M2 | 角色設定（character_master） | ✅ 完成 |
| M3 | 第一章初稿（墨起） | ⏳ 待開始 |
| M4 | 全七章初稿 | ⏳ 待開始 |
| M5 | 風格自檢 + 修訂 | ⏳ 待開始 |

## 寫作順序建議

1. Ch1（墨起）先寫——建立嵌套標記的實作慣例
2. Ch4（墨鏡）第二寫——層間重疊是技術最難的段落
3. Ch7（墨末）第三寫——確認結尾的冷靜基調
4. 其餘按順序補

## 不要做的事

- 不要把嵌套寫成偵探推理（不是在找「真相」）
- 不要讓 AI / 程式介面出現（這不是科幻）
- 不要讓主角「醒來」（沒有救贖）
- 不要用詩意的結尾包裝虛無（虛無就是虛無）
